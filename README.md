# Study Tasks API - Assignment 6

This is a small REST API I made to keep track of tasks for my courses. It lets me add a task, see my tasks, edit one, or delete it. I used **Node.js, Express, and SQLite**. There is no front end for this assignment.

The tasks are saved in a SQLite database file, so they don't disappear when I stop the server.

## How to run it

You need **Node.js 22.13 or newer** and npm. I used Node.js 22. SQLite is included with this Node version, so there is no separate database to install.

1. Open this project folder in VS Code.
2. Open the terminal in this folder and run:

   ```bash
   npm install
   ```

3. Make a copy of `.env.example` and name it `.env`.

   In PowerShell on Windows:

   ```powershell
   Copy-Item .env.example .env
   ```

   On macOS / Linux:

   ```bash
   cp .env.example .env
   ```

4. Keep these values in `.env`:

   ```env
   PORT=3000
   DB_FILE=./data/tasks.db
   ```

5. Start the server:

   ```bash
   npm start
   ```

   You should see `Server running at http://localhost:3000`.

The database file is created automatically inside `data` the first time the server runs. It is not included on GitHub. I put `.env`, the database file, and `node_modules` in `.gitignore`.

**Note:** Node.js 22 might print an experimental SQLite warning. That is from Node's built-in SQLite module and doesn't stop the server.

## Routes

The API uses `http://localhost:3000`. All request and response bodies below are JSON, except DELETE which has no response body.

| Method | Route | What it does | Success code |
| --- | --- | --- | --- |
| GET | `/` | Check that the server is running | 200 |
| GET | `/tasks` | Show all tasks | 200 |
| GET | `/tasks/:id` | Show one task | 200 |
| POST | `/tasks` | Add a task | 201 |
| PUT | `/tasks/:id` | Update a task | 200 |
| DELETE | `/tasks/:id` | Delete a task | 204 |

Opening `http://localhost:3000/` makes a `GET /` request with no body. It returns **200 OK**:

```json
{ "message": "Study Tasks API is running. Go to /tasks to see the tasks." }
```

### 1. POST /tasks

Send JSON like this:

```json
{
  "title": "Finish React exercises",
  "course": "Web Development",
  "completed": false
}
```

Response **201 Created** (the id and date are generated by the database):

```json
{
  "id": 1,
  "title": "Finish React exercises",
  "course": "Web Development",
  "completed": false,
  "createdAt": "2026-11-09 12:00:00"
}
```

`completed` can be left out when adding a task; it will be `false` by default.

### 2. GET /tasks

No request body. Response **200 OK**:

```json
[
  {
    "id": 1,
    "title": "Finish React exercises",
    "course": "Web Development",
    "completed": false,
    "createdAt": "2026-11-09 12:00:00"
  }
]
```

If there are no tasks, the response is `[]`.

### 3. GET /tasks/1

No request body. Response **200 OK**:

```json
{
  "id": 1,
  "title": "Finish React exercises",
  "course": "Web Development",
  "completed": false,
  "createdAt": "2026-11-09 12:00:00"
}
```

### 4. PUT /tasks/1

PUT replaces the editable task information, so I send the title and course again.

Request:

```json
{
  "title": "Review REST API chapter",
  "course": "Web Development",
  "completed": true
}
```

Response **200 OK**:

```json
{
  "id": 1,
  "title": "Review REST API chapter",
  "course": "Web Development",
  "completed": true,
  "createdAt": "2026-11-09 12:00:00"
}
```

### 5. DELETE /tasks/1

No request body. Response **204 No Content**. The task is removed and nothing is returned in the body.

## Error examples

The API also checks the inputs instead of saving bad data.

For example, trying to create a task without a title:

```json
{
  "course": "Web Development"
}
```

Returns **400 Bad Request**:

```json
{ "error": "Title is required and must be 1 to 100 characters." }
```

Trying to get `/tasks/999999` when that task doesn't exist returns **404 Not Found**:

```json
{ "error": "Task not found." }
```

Other cases are handled too: an invalid id gives 400, invalid JSON gives 400, and a route that doesn't exist gives 404. An unexpected server error returns **500 Internal Server Error**:

```json
{ "error": "Something went wrong on the server." }
```

For the task fields, `title` (1-100 characters) and `course` (1-60 characters) are required. `completed` must be a boolean (`true` or `false`) if it is included.

## Testing with Postman

I included the Postman collection here:

`postman/Study_Tasks_API.postman_collection.json`

1. Start the server with `npm start`.
2. In Postman, choose **Import** and select that JSON file.
3. Run the requests in order, starting with **01 - Create a task**. The collection saves the created task id in `taskId` so the other requests use the right id.
4. The collection also includes invalid input, missing task, and malformed JSON examples.

I also added a small automated test for CRUD and error handling. Run it with:

```bash
npm test
```

It uses a temporary SQLite database, not the normal database in `data/tasks.db`.
